### 발표 PDF 생성

Beamer로 발표자료 PDF를 생성한다. 

- LaTeX 배포판 (MiKTeX 또는 TeX Live) — `beamer` 클래스로 컴파일한다.
  - 영문 슬라이드는 `pdflatex`, 한글 슬라이드는 `xelatex`/`lualatex` + CJK 폰트를 쓴다.
  - 예: `pdflatex -output-directory=docs/pptx docs/pptx/deck.tex` (참조·목차 정렬을 위해 2회 실행).
- `pip install pymupdf` — Beamer PDF를 이미지로 렌더해 시각 QA를 수행한다(LibreOffice 불필요).
- 산출물은 PDF로 수행한다.
- 시각 자료(네트워크·파이프라인 등)는 TikZ로, 결과 그림은 `figures/`의 PNG를 `\includegraphics`로 삽입한다.

# 학술 발표 스킬 (Academic Presentations Skill)

## 이 스킬의 구성

두 단계로 이루어지며, 자료를 생성하기 전에 아래 사항을 읽는다:

1. **이 파일** — 콘텐츠, 논증 구조, 그리고 빌드/QA 워크플로우.
2. **slide_patterns.md** — 슬라이드 유형별 구현 패턴(제목, 동기, 방법론, 결과 등)과 확정된 색상·폰트·레이아웃 상수. 모든 시각 규격의 기준(source of truth)이다. 색상이나 폰트 크기를 이 파일에서 다시 선언하지 말고 `slide_patterns.md`에서 가져올 것.

| 작업 | 위치 |
|------|------|
| 콘텐츠 기획, 논증 구조, 슬라이드별 규칙 | 이 파일 → 1~2단계 |
| 슬라이드 유형별 패턴 + 모든 색상·폰트·레이아웃 상수 | slide_patterns.md |
| 타 AI 생성 이미지 삽입 (Codex MCP / ChatGPT 이미지) | 이 파일 → 3단계 |
| .pptx 파일의 기술적 생성·편집·QA | PPTX 스킬 |

## 1단계: 발표 유형 식별

### 논리 서사의 매끄러움 — 작업의 기본값

**우선순위: 논증 구조 → 데이터 → 레이아웃 → 미학.**

슬라이드 별로 증분적으로 논증을 쌓아올린다. 증분적인 논리 쌓기 예시는 다음과 같다.

'''
서론: 다계층 공급망은 복잡하고, 최근 이란 사태와 같이 공급망 붕괴는 심각한 경제적 손실을 초래할 수 있다.
연구 필요성: 서론의 이유로 불확실성을 고려한 공급망 최적화가 중요하다. 
기존 연구 방향성 및 나의 목표: 기존 연구는 보통 정적 상황에서의 최적을 가정했지만, 본 연구에서는 실제 상황에서 발생할 수 있는 미래의 수요 불확실성을 고려한 공급망 최적화 다룬다.
방법론: MPC는 알려진 모델을 기반으로 공급망의 미래 dynamics를 예측하고, 이를 기반으로 미래 상황까지 고려한 최적화 문제를 해결할 수 있기 때문에 이를 택하였다.
비교 실험: 기존 정적인 상황에서의 정책과 비교했을 때, backorder 관리 측면 등에서 확실한 이득이 있고, 운영 관점에서 미래 상황을 고려하는 것이 필요하다는 insight를 제공한다.
'''

### 시각적 / 서사적 
시각적인 자료를 통해 각 페이지에서 말하는 바가 한 눈에 들어오도록 한다. 
발표자가 말하는 내용과 시각 자료가 서로 보완적이어야 한다.
---

## 2단계: 발표 흐름 기획

슬라이드별 개요(제목, 액션 타이틀, 전시 자료 유형)부터 작성합니다.

제안한 제목만 순서대로 읽고, 그것만으로 완전한 논증이 전달되어야 한다. 그렇지 않으면 빌드 전에 개요를 고친다.

기획한 각 슬라이드를 [slide_patterns.md]의 패턴에 매핑한다. 
각 슬라이드의 전시 자료 유형(차트, 표, 그림 등)을 명시하고, 필요하면 AI 생성 이미지로 대체할 수 있는지 검토한다.
---

## 3단계: 생성 단계

각 슬라이드를 [slide_patterns.md]에 작성된 패턴 양식에 기반하여 구현한다. 
모든 색상·폰트·마진 상수는 그 파일에 있다 — 가져와서 재사용하고, 두 번째 팔레트를 절대 하드코딩하지 않는다.

### 디자인 표준 (학술용 오버라이드)

전체 규격은 `slide_patterns.md`에 있고, 타협 불가 규칙은 다음과 같다:

- 모든 콘텐츠 슬라이드는 흰 배경; 전체에 단일 서체; 색상은 최대 3개(primary, accent, emphasis)로 설정한다.
- 본문 텍스트 ≥ 20pt; 콘텐츠 슬라이드당 최대 약 40단어
- 본문은 좌측 정렬, 제목과 축 레이블만 중앙 정렬한다. 결과 슬라이드는 그림 오른쪽, 분석을 왼쪽으로 취한다.
- 색상 대비를 통해 페이지에서의 핵심을 강조한다.
- 화려한 장식요소 (이미지, 그라데이션)을 대부분 금지하되, 전체 프레임워크 설정에서는 각 모듈이 잘 떠올려질 수가 있다면 제한적으로 허용한다.

**중요** 코드 생성 단에서 학술적으로 알맞지 않은 단어를 사용했더라도 발표자료에는 학술적으로 적절한 단어로 바꾼다. 
예를 들어, 실험에서 Metric 1이라고 썼더라도 그에 상응하는 "total operational cost" 로 바꾼다.


### AI 생성 이미지 삽입 (Codex MCP / ChatGPT 이미지)
MCP로 연동된 Codex가 현재 프로젝트를 잘 이해할 수 있도록 claude 측에서 명령을 제공한다.
Codex MCP 이미지 도구(또는 ChatGPT로 생성한 이미지)가 만든 그림은 이미지 파일 형태로 오며, figures 파일에 저장된 것을 삽입해야 한다
또한, Codex MCP가 그림을 생성할 때 목적과 슬라이드에서의 위치를 고려하여 생성하도록 하도록 부탁한다.


**워크플로우:**

1. **파일 확보**:  생성된 이미지를 로컬 경로에 저장한다. 
Codex MCP가 URL을 반환하면 먼저 다운로드하고, base64를 반환하면 디코딩해서 `figures/`에 쓴다.

   ```javascript
   const fs = require("fs");
   fs.writeFileSync("figures/fig_generated.png", Buffer.from(b64, "base64"));
   ```

2. **삽입 전 검증.** 파일이 존재하고 실제 래스터 이미지(PNG/JPEG)이며 크기가 0이 아닌지 확인한다. 
폰트가 깨졌거나 잘못 라벨링한 파일은 조용히 렌더링 하지 않고 수정한다.
또한, AI 생성 이미지 내 주석이 상당히 잘못될 경우가 많기 때문에, 그것을 검증하고 필요하면 다시 생성 요청한다.

3. **비율 보존 확인.** 결과 슬라이드의 그림 영역(16:9에서 좌측 약 5.4")에 맞는 너비/높이를 주되 종횡비를 보존한다:

   ```javascript
   slide.addImage({
     path: "figures/fig_generated.png",
     x: MARGIN, y: 1.15, w: 5.4, h: 3.8,   // 크기: slide_patterns.md의 결과 패턴 기준
     sizing: { type: "contain", w: 5.4, h: 3.8 }
   });
   ```

## 4단계: QA

PPTX 스킬의 전체 QA 절차(markitdown으로 콘텐츠 QA, 렌더링된 슬라이드 이미지로 시각 QA, 클린 패스가 나올 때까지 수정-검증 반복)를 실행하고, **추가로** 학술 체크리스트를 돌린다:

```
□ 모든 콘텐츠 슬라이드에 핵심 문장(그 페이지의 핵심 논리 문장)이 있어야 한다.
□ 타이틀만으로 전체 논증이 증분적으로 이어져야 한다.
□ 슬라이드 내 모든 단어가 학술적으로 적절한 단어인 지 검증한다.
□ 결과 슬라이드당 전시 자료 하나; 각 전시 자료에는 분석이 있어야 한다.
□ AI 생성 이미지에 생성물 표기는 되어 있어야 한다.
□ 마지막에 References 슬라이드를 추가하고 그것을 검증해야 한다.
□ 본문 ≥ 20pt; 콘텐츠 슬라이드당 약 40단어 초과를 권하지 않는다.
```

## 핵심 원칙

- **증분적인 타이틀 논리 구조** 모든 제목은 핵심을 진술하는 완전한 문장이며, 제목만으로 전체 논증이 전달되어야 한다.
- **핵심만 간결하게** 논문 전체를 발표하지 않는다. 주어진 시간에 설득력 있게 전달할 수 있는 주장 하나를 고르고, 나머지는 부록으로 넘긴다.
- **학술적으로 올바른 단어 사용** 검증되지 않은 단어, 줄임말, 은어, 비공식적 표현은 사용하지 않는다.
- **슬라이드당 하나의 통찰.** 결과 슬라이드당 전시 자료 하나, 핵심 발견은 그 위에 직접 강조한다.
- **빌려온 것은 모두 인용**하고, AI 생성물은 표기한다.
- **결론으로 끝낸다** — 결론 슬라이드는 Q&A 내내 화면에 남는다.

## 의존성

- `pip install "markitdown[pptx]"` — QA용 텍스트 추출
- `pip install "aspose-slides"` — pptx를 이미지로 렌더 라이브러리 (레이아웃 감사용)
- `pip install pymupdf"` — Beamer PDF를 이미지로 렌더해 시각 QA 수행
