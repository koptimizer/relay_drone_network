# 글쓰기 스타일

## 전체 유의 사항
- 논문은 실제 학계에서 주로 사용되어 왔던 단어, 문장 구조, 문제를 사용하여 작성한다.
- 개인 스타일을 반영하여 핵심 기여점이 아닌 경우 수동태 위주로 작성한다.
예시: (X) We propose the method | (O) The method is proposed
- 초록은 연구 필요성, 우리가 다루고자 하는 것, 제안하는 방법의 차별성, 그리고 연구 결과 및 인사이트를 흐름대로 작성한다.
- 논문은 초록 내용과 잘 대응되도록 작성한다.

## 운영 인사이트 관련 강조 방법

문헌 자료를 제공하기 전 초록에서 운영 시나리오, 당면 과제, 그리고 연구 기여점을 명확하게 하고 넘어가야 합니다.
추상적인 경영 용어가 아닌 구체적인 운영 용어 (사이클 타임, 리드 타임, 재고 수준, 의존성, 백오더 등)을 사용해야 합니다.
핵심은 운영이기 때문에 각 섹션모두 운영 관점에서 어떤 현상을 유도하고 있는지 염두해야 합니다.
또한, 운영 개념을 명확하게 설명하고, 통계 결과를 실제 운영에 미치는 영향 (공급망 전역 네트워크 관점)으로 해석하고, 이론만을 위한 서술은 피해야 합니다.

## 형식 및 분량

- **길이:**: 길이 제한은 없으나, 최대한 간결하게 표현될 수 있도록 작성 
- **원고 형식**: 단일 열, 두 줄 간격, 12포인트 글꼴, 1인치 여백, 페이지 번호 매기기 "바닥글 없음"
- **인용 스타일:** : APA

## 코드 내용 일치
사용되는 에이전트: `verifier`, `reviewer`
- 코드 구현 증거 수집에는 `verifier` 하위 에이전트를 사용한다.
- 주장된 메서드, 기본값, 메트릭 및 데이터 처리 방식을 실제 코드와 비교한다.
- 누락된 코드, 불일치, 모호한 기본값 및 재현 위험을 지적한다.
- `reviewer` 하위 에이전트를 실행하여 감사 결과물을 넘기고 정리한 tex 파일을 검토한 뒤 다시 tex 파일을 재수정한다.

## 피해야 할 것

- 독자가 핵심 내용을 파악하기 전에 참고 문헌을 장황하게 나열하는 상황
- 누가 어떤 과정을 어떻게 수행했는지 명확하게 밝히지 않는 수동적이고 명사화된 문체
- 실무 관점에서의 관련성을 주장하지만 구체적으로 제시하지 않는 경우
- 포괄적인 것처럼 보이려고 내용을 불필요하게 늘리는 경우 (간소화 검토 필요).
- 표절율 규칙을 위반하는 정형화된 표현.

## 검증 기준

| 글쓰기 수준 | 지향해야 할 것 | 지양해야 할 것 |
|-------------------|-----------|------------------------|

| 도입부 | 첫 페이지에서 문제 및 운영 시나리오 및 난제 제시 | 요점 제시 전 장황한 문헌 설명 |
| 어조 | 구체적인 운영 명사 사용  | 수동적이고 명사로 표현된 경영 추상화 |
| 결과 서술 | 통계를 운영적 결과로 해석 | 운영적 의미 없이 계수만 제시 |
| 실무적 관련성 | 현장 또는 네트워크에서 발생한 구체적인 변화 제시 | 관련성은 주장되지만 구체화되지 않음 |
| 길이 | 간결하게 다듬기 | 내용이 풍부해 보이도록 부풀려짐


## 검증 및 재작성 방법
사용되는 에이전트: `researcher`, `reviewer`

- 시작하기 전에 검토할 내용, 검토 기준(독창성, 실증적 엄밀성, 기준선, 재현성 등), 주장, 그림, 보고된 지표에 필요한 검증 관련 사항을 정리한다. 
- `researcher` 하위 에이전트를 실행하여 tex 파일 결과물에 대한 증거를 수집합니다. 논문, 코드, 인용된 연구, 연결된 실험 결과물을 검사한다. 
- `researcher`의 결과를 관측하고, `reviewer` 하위 에이전트를 실행하고 정리한 tex 파일을 검토한 뒤 다시 tex 파일을 재수정한다.
- 증거 수집이 과도한 소규모 또는 간단한 결과물의 경우, `reviewer` 하위 에이전트를 직접 실행한다.
- 논문 수정 결과물은 tex 파일에 다시 업데이트 되어야 한다.
