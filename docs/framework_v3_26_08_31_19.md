## 1. 왜 계층 구조로 가는가

v2까지 일곱 차례의 수정을 시도했고, **배송 성능을 유의미하게 올린 것은 하나도 없었다.**
제안 방법은 10~17건, 탐욕 휴리스틱은 24건에 머물렀다.

| 시도 | 결과 |
|---|---|
| 통신 하드 제약 | 통신 단절 0건 달성 (성공, 유지) |
| 산개 보상 제거 | 실패 — 1홉 붕괴 유발, 되돌림 |
| 중계 potential 쉐이핑 | 효과 없음 |
| 앵커 페널티 버그 수정 | 공정성만 개선 |
| alpha 하한 / 중계 가중 / 동료 전원 관측 | 셋 다 효과 없음 |
| 행동 파라미터화 (각도 → 벡터) | 붕괴 완화(하락 -40%→-8%), 배송은 변화 없음 |
| 최소 섭동 투영 | 탐욕만 개선, 학습 정책은 변화 없음 |

그런데 지표가 일관되게 한 방향을 가리킨다.

| 지표 | 제안(v2 최선) | 탐욕+중계1 |
|---|---|---|
| 2홉 이상 비율 | **0.64~0.68** | 0.60 |
| 최대 도달 거리 | **730** | 668 |
| **재적재 횟수** | **0.0~0.4** | **3.0** |
| 배송 | 11.5 | 24.5 |

**중계 네트워크는 우리가 더 잘 만든다. 못 하는 것은 왕복 사이클이다.**
배송 5건 → 적재량 소진 → 제어 센터 복귀 → 재적재 → 재출발. 이 사이클은 수백 스텝에 걸쳐 있고,
스텝 단위 연속 제어 정책이 단일 계층으로 잡아내기 어려운 시간 지평이다.

v3는 이 시간 지평 문제를 **의사결정을 두 층으로 분리**해서 다룬다.
상위는 "무엇을 할지"를 드물게, 하위는 "어떻게 갈지"를 매 스텝 결정한다.

## 2. 문제 정의 (v2에서 유지)

재난 지역에서 동질적인 드론 편대가 제어 센터에서 물자를 싣고 다수 목적지에 배송한다.
통신 인프라가 파괴된 상황을 가정하므로, **모든 드론은 항상 제어 센터와 연결되어 있어야 한다** —
직접 통신 반경 안에 있거나, 다른 드론을 거치는 다중 홉 중계로 연결되어야 한다.

| 항목 | 값 |
|---|---|
| 드론 수 | 4 |
| 목적지 수 | 50 |
| 지도 | 1000 × 1000 |
| 통신 반경 | 300 |
| 드론 적재량 | 5 |
| 하역/재적재 소요 | 10 스텝 |
| 최대 속도 | 13.89 / 스텝 |
| 에피소드 상한 | 1000 스텝 |
| 목적함수 | 전 목적지 배송 완료 시간(makespan) 최소화 |

**통신 반경 300의 근거.** 난이도 축 스윕 결과 반경 500에서는 탐욕이 50/50을 완주해 연구가 주장할
영역이 없었다. 300은 (a) 탐욕이 24/50으로 실패하고, (b) **인스턴스마다 최적 중계 대수가 달라
고정 규칙이 원리적으로 맞출 수 없는** 구간이다(고정 최선 22.7 대 인스턴스별 최적 28.2).
이 구간에서 중계 없이 닿는 목적지는 평균 6곳뿐이며, 나머지 44곳은 중계 사슬을 필요로 한다.

## 3. 계층 구조

```
                    ┌─────────────────────────────────────────┐
   HL_EVERY 스텝마다 │  상위 정책 (Manager)                     │
   또는 하위 목표     │  드론별 이산 선택:                        │
   무효화 시          │    · 후보 목적지 K개 중 하나 (배송)        │
                    │    · 제어 센터 복귀 (재적재)               │
                    │    · 현 위치 유지 (중계 담당)              │
                    └────────────────┬────────────────────────┘
                                     │ 하위 목표 g_i (2D 좌표 + 종류)
                                     ▼
   매 스텝            ┌─────────────────────────────────────────┐
                    │  하위 정책 (Worker)                       │
                    │  2D 추력 (v_x, v_y) ∈ [-1,1]²            │
                    │  노름 1로 클리핑 → 변위 = v · max_speed    │
                    └────────────────┬────────────────────────┘
                                     ▼
                    ┌─────────────────────────────────────────┐
                    │  환경: 연결성 하드 제약 (최소 섭동 투영)     │
                    │  제안 변위를 연결 유지 최대치까지 축소        │
                    └─────────────────────────────────────────┘
```

### 3.1 상위 정책 — 무엇을 할지

**행동 공간 (드론별 이산, 크기 K+2).** 후보 목적지 K개(자기 기준 최근접 미배송지), 제어 센터 복귀,
현 위치 유지. 목적지 50개를 그대로 행동으로 두면 행동 공간이 인스턴스 크기에 종속되므로,
**최근접 K개로 제한해 크기를 고정**하고 인스턴스 크기에 무관하게 만든다.

`HOLD`(현 위치 유지)를 넣는 것이 핵심이다. 중계 역할은 "아무 데도 가지 않는 것"이며, 이를
명시적 행동으로 두어야 상위 정책이 **역할 분담을 직접 선택**할 수 있다. v2에서는 중계가 보상
설계로 간접 유도되기만 했고 셋 다 실패했다.

**결정 시점.** `HL_EVERY` 스텝마다, 그리고 하위 목표가 무효화될 때 즉시 재결정한다.
무효화 조건은 (a) 목표 목적지에 도착해 하역을 마침, (b) 다른 드론이 먼저 배송함,
(c) 적재량 0인데 목적지를 향하고 있음, (d) 제어 센터에서 재적재를 마침.

**관측.** 자기 상태(적재량, 제어 센터까지 거리, 홉 깊이), 후보 K개 각각의 상대 위치·거리·
현재 다른 드론이 향하고 있는지 여부, 동료 상태(상대 위치, 적재량, 현재 하위 목표 종류),
남은 목적지 수. 후보를 상대 좌표로 넣어 병진 불변성을 유지한다.

**보상.** 팀 목적함수만 받는다 — 배송 성공, 재적재 성공, 스텝당 시간 페널티. 하위 목표를
고르는 것이 곧 과제 할당이므로, 상위는 "누가 어디로 갈지"의 결과만 평가받는다.

### 3.2 하위 정책 — 어떻게 갈지

**행동 공간.** 2D 추력 벡터 `(v_x, v_y) ∈ [-1,1]²`. 노름이 1을 넘으면 정규화하고,
변위는 `v · max_speed`다. 상하좌우 어느 방향으로든 연속적으로 밀 수 있다.

이 표현은 v2에서 실측으로 얻은 결론이다. 각도 스칼라 표현은 SO(2)의 불연속 표현이라
물리적으로 같은 두 헤딩이 행동 공간의 양 끝에 놓이고(거리 1.993 대 벡터 표현 0.023),
최대 속도를 내려면 tanh 포화가 필요해 SAC의 엔트로피 항이 이를 억제한다(실측 명령 속도 평균
0.511/1.0). 벡터 표현은 두 문제를 동시에 없애고, 실제로 학습 붕괴를 크게 완화했다
(정점 이후 하락 -40% → -8%).

**관측.** 하위 목표까지의 상대 벡터와 거리, 목표 종류(배송/복귀/유지), 자기 적재량과 하역 타이머,
동료 2대의 상대 위치·홉 깊이, 자기 홉 깊이, 직전 스텝의 연결 보정량.

**보상.** 하위 목표에 대한 조밀한 진척 보상만 받는다 — 목표까지 거리 감소분, 도달 보너스,
연결 보정으로 잘려나간 변위에 비례하는 페널티. 팀 보상은 받지 않는다. 하위의 임무는
"주어진 목표에 빨리 도달하는 것"으로 한정되며, 이는 상위의 과제 할당과 관심사가 분리된다.

### 3.3 연결성 — 학습이 아니라 환경이 보장

연결성은 보상 항이 아니라 **환경의 하드 제약**이다. 제안된 이동이 누군가를 고립시키면,
연결이 유지되는 최대 변위까지 축소한다(최소 섭동 투영). 축소 대상은 "제한했을 때 연결되는
드론 수가 가장 많아지는 드론"으로 고르고 동점은 무작위로 깬다.

이 설계의 근거는 문헌과 실측 양쪽에 있다. 동일 과제를 페널티로 학습하면 에피소드 리턴 0.5,
마스킹으로 하면 40.0이라는 통제 비교가 있고, 연결성을 CMDP 비용으로 다룬 연구는 연결률 73%에서
정체했다. 순수 CPO는 연결률 97%를 얻는 대신 과제 성공률이 5%로 붕괴했다 —
**어떤 soft 방법도 두 마리 토끼를 잡지 못했다.** 우리 구현은 학습 9,844 에피소드와 평가 수백
롤아웃에서 통신 단절 0건을 유지했다.

동점을 무작위로 깨는 것은 사소해 보이지만 필수다. 결정론적으로 깨면 사슬을 붙잡는 앵커 드론이
반복 선택되어 굶는다 — 실측에서 배송이 29.4 → 22.2로 떨어졌다.

## 4. 학습 방식

**CTDE (Centralized Training, Decentralized Execution)** 를 두 층 모두에 적용한다.
Actor는 각자의 local 관측만 보고, Critic은 학습 시에만 global state를 본다.

| | 상위 | 하위 |
|---|---|---|
| 알고리즘 | 이산 SAC (categorical) | 연속 SAC (Gaussian + tanh) |
| 행동 | K+2 중 하나 | 2D 추력 |
| 결정 주기 | HL_EVERY 스텝 또는 목표 무효화 시 | 매 스텝 |
| 보상 | 팀 목적함수 (배송·재적재·시간) | 하위 목표 진척 (조밀) |
| Critic 입력 | global state + 전체 상위 행동 | global state + 전체 추력 |

**단계적 구축.** 두 층을 동시에 학습시키면 실패 시 원인을 가릴 수 없으므로 순서를 둔다.

1. **v3.0 — 하위만 학습.** 상위를 규칙(최근접 미배송지 / 적재량 0이면 복귀)으로 고정하고
   하위 정책이 목표 도달을 학습할 수 있는지 확인한다. 이 구성은 "탐욕 + 학습된 저수준 제어"이므로
   탐욕 베이스라인과 직접 비교되며, 계층 분해 자체의 타당성을 검증한다.
2. **v3.1 — 상위만 학습.** 하위를 v3.0에서 얻은 정책으로 고정하고 상위 이산 정책을 학습한다.
   여기서 처음으로 "학습된 과제 할당이 규칙 기반 할당을 이기는가"를 잰다.
3. **v3.2 — 동시 학습.** 두 층을 함께 미세조정한다.

## 5. v2에서 제거한 것

효과가 측정되지 않은 기제를 모두 걷어내 메서드를 가볍게 한다. 각 항목은 실험으로 기각됐다.

| 제거 대상 | 기각 근거 |
|---|---|
| 중계 potential 쉐이핑 (`relay_w`) | 반경 500·300 모두에서 정점 성능 개선 없음. 분산만 증가 |
| 중계 가중 보상 재분배 (`relay_credit`) | 최종 비교에서 오히려 최하위 (9.4 대 11.5) |
| alpha 하한 (`alpha_min`) | 정점이 ep50으로 가장 이르고 최종 성능 개선 없음 |
| 동료 전원 관측 (`n_peers=3`) | 정점 성능 기준선과 동일, 홉 지표는 오히려 최저 |
| 각도 행동 표현 (`action_mode=angle`) | SO(2) 불연속. 벡터 표현이 붕괴를 5배 완화 |
| 전체 취소 투영 (`projection=cancel`) | 최소 섭동이 팀 총변위·성능 모두 우위 |
| 산개 보상 (스텝당 +0.05/쌍) | 시간 페널티의 150배로 보상 해킹 경로. v1에서 이미 제거 |

**유지하는 것:** 연결성 하드 제약(최소 섭동 투영, 무작위 동점 처리), 벡터 행동 표현,
포텐셜 기반 거리 쉐이핑, 시간 페널티, 팀 보상(배송·재적재), 조기 종료와 홀드아웃 평가,
전 지표 계측(배송·재적재·미활동 드론·홉 깊이·최대 도달·이동 차단·통신 단절).

**판단 보류:** 뭉침 페널티는 단독으로 검증한 적이 없다. v3에서는 상위 정책이 서로 다른 목적지를
할당하면 자연히 산개하므로 불필요할 가능성이 높으나, 제거 여부는 절제 실험으로 정한다.

## 6. 평가 규약

**홀드아웃 인스턴스.** 학습은 고정 지도, 평가는 학습에 쓰지 않은 시드로 생성한 인스턴스를 쓴다.
학습 중 조기 종료 판정은 시드 201~206, 최종 보고는 시드 101~130(30개)이다. 매 평가가 동일 시드를
쓰므로 체크포인트 간 비교가 짝지어져 인스턴스 난이도 분산이 제거된다.

*알려진 한계:* 학습이 여전히 고정 지도 하나를 쓰므로 인스턴스 암기 문제가 남아 있다.
인스턴스 무작위화는 v3 이후 과제로 미뤄져 있다.

**주 지표.** 배송 완료 수(50 중). makespan은 전량 완주 시에만 정의되는데 아직 아무도 완주하지
못했으므로 `t_last_deliv`(마지막 배송 시각)를 보조로 쓴다.

**보조 지표.** 재적재 횟수(왕복 사이클 학습 여부), 홉 깊이 2 이상 비율과 최대 도달 거리(중계
네트워크 활용도), 미활동 드론 수(역할 분담), 이동 차단(제약 마찰), 통신 단절(제약 무결성 검사 —
항상 0이어야 한다).

**베이스라인.** 같은 환경·같은 인스턴스에서 규칙 정책을 굴린다.

| 베이스라인 | 반경 300 성능 |
|---|---|
| 무작위 | 3.7 / 50 |
| 탐욕 (최근접 미배송지, 비면 복귀) | 23.3 / 50 |
| **탐욕 + 중계 1대 고정** | **24.5 / 50** |
| 탐욕 + 중계 2대 고정 | 19.1 / 50 |

**MILP를 만들지 않는 이유.** 우리 문제를 MILP로 정식화하려면 비행 중 위치를 표현해야 하는데,
노드 기반 라우팅 정식화에서는 이동 중 드론에 좌표가 없다. 공간을 격자화하거나 후보 호버링
지점을 사전 지정해야 하며, 후자는 그 자체가 placement 문제다. 같은 드론이 배송과 중계를 겸하므로
Yanmaz(2022)처럼 placement를 하위문제로 분리할 수도 없어 **결합 placement-routing 문제**가 된다.
문헌상 트럭+드론 1대 MILP의 증명된 최적해 한계가 고객 10명, 순수 min-max mTSP도 도시 50~75개에
에이전트 2대가 한계이므로, 시간 인덱스 위치 변수와 매 시점 연결 흐름 제약을 얹으면 목적지 4~6곳
수준에서 막힌다. "MILP는 확장되지 않는다"는 주장은 문헌 인용으로 충분하며, 직접 구현해 실패를
보이는 것보다 안전하다.

**정직한 주장 범위.** 문헌상 RL 라우팅의 최고 설정도 잘 튜닝된 휴리스틱(LKH3)보다 4% 나쁘다.
따라서 해의 품질 우위를 주장해서는 안 되며, 주장 가능한 것은 (i) 통신 그래프가 매 스텝 바뀌는
상황에서의 온라인 재결정과 (ii) 스텝당 추론 지연이다. 또한 LKH3·OR-Tools·ScheduleNet은 용량·
재적재·통신 제약이 없는 완화 문제를 풀므로 head-to-head 비교군이 아니라 **완화 참조 상계**로만
쓸 수 있다.

## 8. 성공·실패 판정 기준

미리 정해두어 사후 합리화를 막는다.

- **v3.0 성공 조건:** 하위 정책이 규칙 상위와 결합해 탐욕 베이스라인(24.5)의 90% 이상, 즉
  **22 이상**. 이는 계층 분해가 최소한 손해가 아님을 뜻한다.
- **v3.1 성공 조건:** 학습된 상위가 규칙 상위를 넘어 **24.5 초과**. 넘으면 학습된 과제 할당이
  고정 규칙보다 낫다는 주장이 성립한다.
- **의미 있는 기여 수준:** 난이도 스윕이 시사한 인스턴스별 적응 상한이 28.2이므로,
  **28 이상**이면 에피소드 내 역할 전환까지 활용했다는 근거가 된다.
- **실패 시:** v3.0이 22에 못 미치면 계층 분해 자체가 이 문제에 맞지 않는다는 뜻이므로,
  RL 접근을 계속 밀기보다 난이도 축 스윕과 중계 대수 최적성 관측을 기여로 정리하는 방향을 검토한다.
