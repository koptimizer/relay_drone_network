## 2. 무엇을 바꿨고 어떻게 검증했는가

### 2.1 통신 연결을 보상이 아니라 하드 제약으로

**구버전의 결함.** 이동 후 연결이 끊길 드론의 이동을 취소하는 로직이 있었으나 취소 대상이
**피해자**였지 원인 제공자가 아니었다. 드론 A가 멀리 날아가 하역 중이던(`timer > 0`) 드론 B를
고립시키면, B는 애초에 이동 의사가 없어 취소 대상에서 빠지고 그대로 -100과 강제 종료를 맞는다.
구·신 환경을 나란히 돌려 재현했다.

```
[구버전] step 35: 드론 [3] 통신 단절 → 보상 [0.0, 0.0, 0.0, -100.0], 강제종료=True
[신버전] 60스텝 내내 전원 연결 유지 (이동 차단 25회)
```

3번 드론은 하역 중이라 어떤 행동도 할 수 없었는데 -100을 받고, 정작 원인인 0·1·2번은 0.0을
받는다. 회피 불가능한 페널티가 발표 시점 5,000 에피소드 내내 학습 신호로 들어갔다.

**수정.** 전원이 연결될 때까지 **원인이 되는 이동**을 하나씩 되돌린다. 모든 이동을 되돌리면
직전 위치(연결 상태)로 복귀하므로 루프는 반드시 연결 상태에서 종료하며, 따라서 단절이 구조적으로
불가능하다. **학습 9,844 에피소드 + 평가 150 롤아웃에서 단절 0건**으로 확인했다.
반면 pre-v1은 평가 30회 중 **1회 단절**이 발생했다.

문헌도 이 방향을 지지한다. 동일 과제를 페널티로 학습하면 에피소드 리턴 0.5, 마스킹으로 하면
40.0이라는 통제 비교가 있고, 연결성을 CMDP 비용으로 다룬 연구는 연결률 73%에서 정체했다.
순수 CPO는 연결률 97%를 얻는 대신 과제 성공률이 5%로 붕괴했다 — **어떤 soft 방법도 두 마리
토끼를 잡지 못했다** (상세: `ref/marl-relay-drone-delivery.md` §2.1).

### 2.2 중계 드론이 구조적으로 처벌받던 문제

연결성 강제 로직이 동점일 때 항상 가장 낮은 인덱스의 이동을 취소해서, **사슬을 붙잡는 앵커
드론이 페널티를 독식**했다. 20 에피소드 전부에서 0번 드론이 앵커였고 평균 165회 차단을 혼자 맞았다.
정책이 공유 MLP + `drone_id` one-hot을 쓰므로 "0번은 무엇을 해도 손해"를 학습하게 된다.

동점을 무작위로 깨도록 바꿔 앵커 역할이 분산됨을 확인했다(`[20,0,0,0]` → `[4,8,6,2]` / 20ep).
차단 페널티도 고정 -0.1에서 **취소된 변위에 비례**하도록 바꿨다. 부수 효과로 속도 0을 명령해
중계 대기 중인 드론은 더 이상 처벌받지 않는다.

### 2.3 보상 해킹 경로 제거

구버전은 잘 벌어진 드론 쌍마다 스텝당 +0.05를 주었고 시간 페널티는 -0.001이었다. 드론 4대면
6쌍이므로 이상적 대형에서 드론당 약 +0.15 대 -0.001, **약 150배**다. 배송하지 않고 대형만
유지하는 것이 빠지기 쉬운 국소 최적이 된다. 이는 potential-based reward shaping 문헌의 고전적
실패 사례와 같은 구조다 — 목표 접근에 보상을 주자 자전거가 목표 주위를 맴돌고, 공 접촉에 보상을
주자 축구 에이전트가 진동하듯 반복 접촉한다.

산개 보상을 제거하고 시간 페널티를 -0.01로 올렸다. 정지 대형 유지 시 스텝당 보상이 전 드론
-0.01임을 실측했다. **다만 이 수정에는 별도의 실패가 있었다 — §7.1 참조.**

### 2.4 측정 지표

발표 시점에는 최소화 대상인 배송 시간이 전혀 측정되지 않았다. 추가한 것은 배송 완료 수, 완료율,
makespan, **드론별 배송 건수**, 미활동 드론 수, 재적재 횟수, 이동 차단 횟수, 통신 단절 여부,
**홉 깊이 2 이상 비율**, **최대 도달 거리**, 마지막 배송 시각이다.

Actor Loss가 구조적으로 한 번도 기록되지 않던 버그도 고쳤다. 두 로깅 조건의 주기가 영원히
어긋나 있었고, 실제로 발표에 쓰인 5,000 에피소드 런의 TensorBoard에는 Actor 태그가 없다.

**홉 지표를 넣은 것이 이번 작업에서 가장 값어치 있었다.** 하드 제약 하에서는 문헌이 쓰는
Available UAV Ratio가 정의상 항상 1.0이라 아무 정보도 주지 않는다. 계획된 지표가 전부
"끊겼는가"만 묻고 "얼마나 멀리 뻗었는가"를 묻지 않았기 때문에, §6.1의 붕괴가 2,500 에피소드
동안 발견되지 않았다.

## 3. 발표에서 지적된 현상별 해결 여부

**"통신이 끊기면 대량의 penalty 및 강제 종료" (12p)** — 발동하지 않는다. 학습 9,844 에피소드,
평가 150 롤아웃 단절 0건. 회피 불가능한 -100이 학습 신호에서 사라졌다.

**"일부 드론은 제대로 임무를 수행하지 못함" (18p)** — 정량화하고 해결했다. 미활동 드론이
pre-v1 2.23명에서 최적 체크포인트 0.20명(Run A) / 0.07명(Run C)으로 줄었다. 4대 중 사실상
전원이 배송에 참여한다. **단, 과학습 구간에서는 1.83~2.30으로 되돌아간다.**

**"제어 센터 통신 구역 밖도 릴레이 네트워크를 통해 배송 수행 확인" (18p)** — **이 서술은
홀드아웃 평가에서 뒷받침되지 않는다.** pre-v1의 2홉 이상 비율은 0.05, 최대 도달 거리는 441로
통신 반경 500에도 못 미친다. 즉 릴레이 네트워크를 사실상 형성하지 않는다. 반면 v1 최적
체크포인트는 2홉+ 0.44~0.45, 최대 도달 833~873으로 **실제로 중계 사슬을 만들어 반경 밖까지
나간다.** 발표에서 주장하려던 현상이 v1에서 비로소 관측된 셈이다.

**"멀리 있는 배송지까지 배송을 완료하지 못함" (18p)** — 미해결. 다섯 모델 모두 전량 완주 0/30이며
makespan은 한 번도 기록되지 않았다.

## 4. 왜 성능이 4배가 되었는가 — 구조적 설명

홀드아웃 30개 인스턴스에서 **제어 센터 직접 통신 반경(500) 안에 있는 목적지는 평균 19.6곳**이다
(범위 13~27). 나머지 30곳은 **중계 사슬 없이는 물리적으로 도달할 수 없다.**

따라서 릴레이를 쓰지 않는 정책의 배송은 20건 근처가 구조적 상한이고, 실제로는 탐색 효율 때문에
그보다 훨씬 낮다. pre-v1(2홉+ 0.05)이 3.8건에 그친 것과, v1 최적(2홉+ 0.44)이 16.1건을 낸 것이
이 상한 구조와 정합적이다.

체크포인트 48개를 홀드아웃에서 훑은 결과 이 관계는 강한 상관으로 나타난다.

- corr(2홉+ 비율, 배송 수) = **+0.89**
- corr(최대 도달 거리, 배송 수) = **+0.93**

`figures/holdout_sweep_v1_26_08_25_04.png` 오른쪽 산점도가 이 관계다.

**해석의 한계.** 위는 상관이며, 두 값이 모두 학습량과 함께 단조 감소하므로 공통 원인일 수
있다. 다만 "반경 밖 30곳은 중계 없이 도달 불가"라는 것은 기하학적 사실이므로, **중계가 20건
이상 배송의 필요조건**이라는 방향의 인과는 성립한다. 반대 방향(중계가 늘면 반드시 배송이 는다)은
주장하지 않는다.

- **통신 가능 구역 이탈 방지** — 5회 전부 단절 0. 하드 제약이 시각적으로도 작동한다.
- **릴레이 네트워크 형성** — 에피소드 1 스냅샷에서 D1이 제어 센터 통신권 경계에 자리 잡고
  반경 밖 드론을 중계로 연결한다(최대 도달 959, 통신 반경의 약 2배). pre-v1(도달 441)과 가장
  뚜렷한 차이다.
- **임무 분담** — 에피소드 1·4·5에서 드론별 배송이 [5,5,5,5] 등으로, 전원이 적재량을 소진한다.

**약점도 함께 드러난다.** 에피소드 3은 8/50으로 무너지고 드론별 배송이 [4,0,3,1]이다. 인스턴스에
따른 편차가 크며(±3.6), §6.2의 암기 문제와 정합적이다. 또한 스냅샷의 `blocked 914`는 1000스텝 중
914번의 이동이 연결 유지를 위해 취소되었다는 뜻으로, 시간 낭비가 상당하다 — §2.1에서 언급한
최소 섭동 투영으로 개선할 여지가 있다.

## 6. 새로 드러난 문제

### 6.1 학습할수록 성능이 붕괴한다 (최우선 과제)

두 실행 모두 **400~600 에피소드에서 정점을 찍고 이후 단조 하락**한다.

| 실행 | 최적 | 최종 | 하락폭 |
|---|---|---|---|
| Run A | ep600 → 16.1건 | ep6590 → 4.3건 | **-73%** |
| Run C | ep400 → 15.9건 | ep3250 → 3.0건 | **-81%** |

동시에 릴레이 네트워크가 사라진다. 2홉+ 비율이 0.64 → 0.02로, 최대 도달 거리가 939 → 395로
**직접 통신 반경 500 아래까지 후퇴**한다. 즉 정책이 중계 네트워크를 버리고 제어 센터 주변으로
움츠러든다.

이것이 발표 자료의 관찰과 이어진다. 발표의 5,000 에피소드 모델이 릴레이를 형성하지 않았던 것은
**학습이 부족해서가 아니라 이미 이 붕괴 구간에 들어가 있었기 때문**일 가능성이 높다.

**원인은 규명하지 못했다.** 남은 후보는 다음과 같다.

1. **탐색 붕괴** — alpha가 0.1에서 0.016까지 단조 감소한다. 중계 사슬처럼 협조가 필요한
   행동은 탐색 없이는 유지되기 어렵다.
2. **중계 역할의 보상 구조** — 중계를 맡은 드론은 배송 보상을 못 받고, 팀 보상은
   `team_r.mean()`으로 평균되어 개별 기여가 1/N로 희석된다. 문헌은 중계 기여를 3배 가중하는
   역할 분화 사례를 제시한다.
3. **관측의 한계** — 각 드론이 동료 3명 중 2명만 관측하므로 **3자 중계 관계를 표현할 수 없다.**
   드론 4대로 사슬을 만들려면 세 동료의 배치를 동시에 알아야 한다.

### 6.2 고정 지도 학습으로 인한 인스턴스 암기

발표 자료 모델과 Run A·C 모두 **하나의 고정 지도로 학습**한다. 발표 당시에는 지도 로딩이 실패해
매 실행마다 뽑힌 난수 지도 하나를 5,000 에피소드 내내 썼다(그 지도는 저장되지 않아 발표 수치를
재현할 방법이 없다).

"재난 상황에서 빠른 추론으로 대응한다"는 이 연구의 전제는 **처음 보는 재난 상황에 대응하는
것**인데, 현재 학습 설정은 그것을 훈련하지 않는다. 에피소드마다 인스턴스를 무작위화하는 것은
한 줄 변경이지만 실험 설계를 바꾸므로 결정을 미뤘다.

### 6.3 중계 potential 쉐이핑은 효과가 없었다

Run C에 넣은 potential 기반 중계 유인
($\Phi(s) = w\cdot|\{(i,j): 300 \le d_{ij} \le 480\}|$, $F = \Phi(s')-\Phi(s)$, $w=2.0$)은
**정점 성능을 개선하지 못했다**(15.9 대 A의 16.1). 오히려 분산이 커졌고(±5.1 대 ±3.6) 붕괴가
더 빨랐다. 이 가중치는 튜닝하지 않은 값이므로 "이 접근이 틀렸다"가 아니라 "$w=2.0$에서는
효과가 없었다"가 정확한 결론이다.

## 7. 이 작업에서 틀렸던 판단

데이터로 뒤집힌 판단을 기록한다. 남기지 않으면 같은 실수를 반복하게 된다.

### 7.1 "연결이 하드 제약이므로 릴레이 사슬은 구조적으로 유지된다"

산개 보상을 제거하며 세운 근거인데 **반증됐다.** 하드 제약은 사슬이 *끊어지는 것*만 막고 사슬을
*만들도록* 유도하지 않는다. 제어 센터 옆에 뭉쳐 있어도 제약은 완벽히 만족된다(무작위 정책
12,000스텝: 홉 분포 {1: 1.0}, 위반 0). **제약 만족과 목표 달성을 혼동한 오류**다.

### 7.2 "Run C가 Run A보다 명확히 낫다"

초기 51 에피소드만 보고 내린 판단이었다. 최종 결과는 정점이 사실상 동률(15.9 대 16.1)이고
분산은 C가 크며 붕괴는 C가 빠르다. **구간을 맞추지 않고 비교한 오류.** 홀드아웃 비교에서
C의 정점 부근 체크포인트와 A의 하락 이후 체크포인트를 맞붙인 것도 같은 실수였다.

### 7.3 "홉 붕괴가 성능 저하의 원인이라는 인과는 확인되지 않았다"

5개 시드, 실행 C 단독의 노이즈 큰 측정으로 내린 판단이었다. 체크포인트 48개를 8개 시드로 훑은
결과 상관이 +0.89로 뚜렷하고, §4의 기하학적 상한 논거까지 더하면 **최소한 필요조건 방향의
인과는 성립한다.** 과소 주장이었다.

### 7.4 "우리 구현이 문헌의 투영 + 비례 페널티 조합과 일치한다"

당시 페널티는 고정 -0.1이었다. §2.2에서 비례로 바꾼 뒤에야 성립한다.

## 8. 다음 단계

**즉시 반영 가능**

1. **조기 종료 기준 도입.** 현재 설정에서 최적 지점은 400~600 에피소드다. 홀드아웃 배송 수를
   주기적으로 재고, 개선이 멈추면 멈춰야 한다. 지금은 좋은 정책을 만든 뒤 계속 학습해서 망가뜨리고 있다.
2. **행동 파라미터화 교체.** 각도 스칼라는 SO(2)의 불연속 표현으로 헤딩 0과 $2\pi$가 행동 공간
   양 끝에 놓인다. 속도 벡터 출력으로 바꾸면 연결성 투영과도 자연스럽게 결합된다
   (`ref/marl-relay-drone-delivery.md` §2.3).

**결정 필요**

3. **인스턴스 무작위화** (§6.2). 연구 전제와 직결되나 실험 설계가 바뀐다.
4. **붕괴 원인 규명 순서** (§6.1). 탐색 붕괴 / 중계 보상 구조 / 관측 한계 중 하나씩 격리 실험.
   개인적으로는 관측 한계(3자 중계 관계 표현 불가)가 가장 근본적이라고 본다.

**논문 작성 시**

5. 발표 자료의 선행연구 위치 설정을 수정해야 한다. 갭 주장이 현재 형태로는 방어되지 않고,
   인용 오류 4건과 누락 필수 문헌(ScheduleNet)이 있다. `ref/marl-relay-drone-delivery.md` §1 참조.
6. 베이스라인으로 계획한 LKH3·OR-Tools·ScheduleNet은 용량·재적재·통신이 없는 min-max mTSP를
   풀므로 head-to-head 비교군이 아니라 완화 참조 상계다. 같은 문제를 놓고 겨룰 수 있는 비학습
   대조군은 Yanmaz의 Steiner point 중계 배치뿐이다.
